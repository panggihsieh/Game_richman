# Richman 遊戲專案規劃與設計

Richman 是一個可在瀏覽器執行的互動式大富翁風格遊戲。專案目前以靜態網頁形式實作，適合部署到 GitHub Pages、校園活動頁面、教學現場或本機瀏覽器中使用。

本專案的核心目標是做出一個容易操作、可快速開始、具備派對感與課堂互動感的棋盤遊戲畫面。

## 專案定位

- 遊戲類型：瀏覽器版棋盤派對遊戲
- 遊玩方式：2 到 8 位玩家輪流擲骰、移動、累積分數
- 使用情境：教學活動、班級競賽、展示互動、主題遊戲
- 技術形式：純 HTML、CSS、JavaScript
- 部署方式：可直接用靜態伺服器或 GitHub Pages 執行

## 目前功能

- 比賽人數可調整為 2 到 8 人，預設為 2 人
- 玩家可輸入名稱
- 玩家可上傳頭像或使用 Webcam 拍攝頭像
- 棋盤包含 12 個主題格子，採 4+2+4+2 長方形外框路線
- 每個格子可使用內建圖片，也可自行上傳替換圖片
- 可設定比賽時間，預設 1 分鐘
- 可開始比賽、擲骰前進、累積分數
- 可緊急停止並重置比賽
- 排行榜會依分數排序
- 比賽結束後標示冠軍
- 支援全螢幕遊戲模式

## 畫面設計

整體畫面分成三個主要區域：

1. 左側設定面板

   用於設定遊戲標題、查看玩家資料、調整玩家名稱、分數與頭像。

2. 中央遊戲區

   放置主棋盤、倒數計時器、中央骰子、開始與擲骰操作。這是遊戲進行時的主要視覺焦點。

3. 右側格子編輯面板

   用於修改每個棋盤格子的名稱與圖片，方便依不同主題活動快速換皮。

在全螢幕模式下，左右兩側面板會隱藏，只保留中央遊戲區，讓投影或大螢幕展示更乾淨。

## 遊戲流程

1. 設定遊戲標題、玩家名稱與頭像。
2. 視需要調整棋盤格子的圖片與名稱。
3. 設定比賽時間。
4. 點擊開始比賽。
5. 玩家依序擲骰並前進。
6. 玩家依骰子點數增加分數。
7. 時間結束後，最高分玩家成為冠軍。

## 驚喜與刺激元素

目前已加入下列互動效果，讓遊戲過程不只是數字更新，而是有節奏、有期待感。

### 骰子動畫

- 擲骰時，骰子數字會快速跳動。
- 結果出現時，骰子會放大彈跳。
- 目的：讓擲骰從普通點擊變成一次小型揭曉事件。

### 落點閃光

- 玩家停在格子時，落點格子會放大並出現金色光暈。
- 格子名稱列會變成亮色漸層。
- 目的：強化「踩到這一格」的命中感。

### 最後 10 秒危急模式

- 倒數最後 10 秒，計時器轉為紅色警示。
- 最後 3 秒，全畫面會出現紅色閃爍邊框。
- 目的：讓比賽尾聲自然形成高潮。

### 排名變動動畫

- 當玩家排名上升時，排行榜中的玩家標籤會跳動並高亮。
- 目的：讓超車與追分更容易被注意到。

### 隨機事件卡與特殊格

- 玩家停下後可能觸發翻牌事件，例如加倍得分、退後、偷分、交換位置或全員洗牌。
- 棋盤上有加分、幸運、神秘、交換、陷阱等特殊格。
- 目的：讓每次落點都有風險與期待。

### 超車提示與結算秀

- 玩家排名上升時會顯示超車或新領先者提示。
- 比賽結束會顯示冠軍聚光卡與前三名摘要，並播放結算音效。

更完整的驚喜設計紀錄可參考 [驚喜.md](./驚喜.md)。

## 視覺風格

- 風格方向：明亮、清楚、活動感強
- 主要色彩：紅、藍、綠、黃搭配深色文字
- 棋盤格子：以圖片作為主視覺，搭配深色標籤列
- 互動回饋：以放大、閃光、跳動、脈衝作為主要動畫語言
- 全螢幕模式：減少控制面板干擾，讓玩家專注於棋盤與倒數

## 技術設計

### 檔案結構

```text
.
├── index.html
├── app.js
├── styles.css
├── README.md
├── 驚喜.md
├── assets/
│   └── stages/
└── scripts/
    └── download-stage-images.mjs
```

### 核心檔案

- `index.html`：頁面結構、主要控制按鈕、棋盤容器與對話框。
- `styles.css`：版面、棋盤、玩家卡、動畫、全螢幕與響應式設計。
- `app.js`：遊戲狀態、玩家資料、棋盤渲染、擲骰流程、倒數計時、圖片上傳與 Webcam。
- `assets/stages/`：內建棋盤格子圖片。
- `scripts/download-stage-images.mjs`：下載或更新主題圖片用的輔助腳本。

## 狀態設計

目前主要狀態集中在 `app.js`：

- `players`：玩家名稱、分數、位置、頭像與顏色。
- `stages`：棋盤格子的名稱、圖片、顏色與自訂圖片。
- `currentTurn`：目前輪到哪位玩家。
- `matchSeconds` / `remainingSeconds`：比賽總時間與剩餘時間。
- `matchRunning`：比賽是否進行中。
- `rolling`：是否正在擲骰，避免重複點擊。
- `championPlayerId`：比賽結束後的冠軍玩家。
- `activeMovingPlayerId`：正在移動的玩家，用於 token 動畫。
- `landingStageId`：剛落點的格子，用於落點閃光。
- `leaderboardPreviousOrder`：前一次排行榜順序，用於判斷排名是否上升。

## 執行方式

可以用簡單靜態伺服器啟動：

```bash
python -m http.server 3000
```

然後在瀏覽器開啟：

```text
http://localhost:3000/
```

也可以部署到 GitHub Pages 或其他靜態網站服務。

## 後續規劃

### 第一階段：提升遊戲張力

- 加入事件機率與特殊格規則設定
- 加入最近事件紀錄區
- 補上最後 10 秒警示音

### 第二階段：提升可編輯性

- 讓每個格子可設定分數或事件
- 讓不同人數規則有更細緻的平衡設定
- 讓遊戲規則可在 UI 中設定
- 匯出與匯入遊戲設定

### 第三階段：提升穩定性與維護性

- 拆分 `app.js` 中的遊戲邏輯、畫面渲染與媒體處理
- 建立統一的事件提示系統
- 補上基本互動測試
- 整理文字編碼，確保中文內容在所有環境下正常顯示

## 設計原則

- 操作要少：活動現場應該能快速開始。
- 回饋要明顯：擲骰、移動、落點、排名變化都應該有清楚反應。
- 刺激要有節奏：平常畫面穩定，關鍵時刻才放大、閃光或警示。
- 主題要容易替換：格子圖片與名稱應該能支援不同活動主題。
- 大螢幕要清楚：全螢幕模式下，棋盤、倒數與排行榜必須一眼看懂。
